# Brand

## Identity

`vibedating` is local-first dating by AI token-use league.

The npm package is `vibedate`. The CLI accepts `vibedate` and `vibedating`.

It belongs to the Vibe Suite and uses `@pooriaarab/vibe-core`.

## Audience

The product serves people who use agentic coding tools in their daily work.

They value playful discovery, verifiable identity, and control over shared data.

## Promise

Local harness logs place a user in a broad lifetime-token league.

Users can meet people in nearby leagues without sharing raw token or project totals.

Live matching stays opt-in and uses peer-to-peer discovery.

## Voice

Lead with “Dating by tokens.” Keep the joke clear and the privacy details exact.

Use developer language that appears in the product: harness, league, handle, and local-first.

Be playful about token use. Be precise about verification, storage, and network behavior.

Do not describe a self-report or demo value as verified.

## Message hierarchy

1. Match by broad token-use league.
2. Raw usage and project details stay local.
3. Live matching is peer-to-peer and opt-in.
4. Signed identities bind persistent handles to peers.

## Naming

Use these league names: `1M`, `5M`, `10M`, `100M`, and `1B+`.

Use `vibedating` for the product. Use `vibedate` for the npm package.

Handles are pseudonymous. Do not present them as legal or real-world identity.

## Claims

The README is the claim source. Code and tests must support any stronger wording.

Network hellos contain handle, league, harness, verification, public-key, nonce, and signature fields.

The product has no central matching database. Hyperswarm provides live peer discovery.

## Assets

The logo is `branding/logo.png`. The launch video is `branding/launch-video.mp4`.

`docs/prototype.html` is the prototype. `src/web-app-html.ts` is the shipped local web app.

## Do's and don'ts

Do distinguish usage verification from signed identity verification.

Don't claim that raw usage, project totals, or private logs cross the peer connection.
